# 分析注释规范

注释服务的读者是"读过摘要、还没读正文的人"。他读这一段时想知道三件事：这段说了什么、这段为什么存在、这段在整篇文章的推理链条上占什么位置。因此每段固定三栏，一栏回答一个问题。

## 三栏分工

### 1. `summary` — 这段讲了什么

按信息类型逐项说清，不要复述句子：

- 提出了什么主张/定义/假设；
- 给出了哪些证据（数据、实验、引用、反例）；
- 做了哪些限定（条件、范围、例外）。

写法：先一句总括，再列 2–4 个要点。允许出现原文里的数字，但不要整段复制原文。**不许**与 `zh` 高度重合，也不许只写"介绍了背景"。

### 2. `function` — 这段起什么作用

给出功能判断，并说明依据（依据通常是句式、位置、与上下段的衔接词）。常用功能标签：

| 标签 | 典型触发 |
|---|---|
| 建立背景 | 领域现状、公认事实、"Recent work has..." |
| 界定问题 | "However"、"remains challenging"、提出问题句 |
| 综述前人 | 罗列方法 + 引用密集 |
| 指出缺口 | "none of these"、"fails to"、"does not address" |
| 提出方案 | "we propose"、"我们的做法是" |
| 说明实现 | 架构、算法、训练细节 |
| 给出证据 | 实验设置、主结果、消融 |
| 解释机制 | "This is because"、"可能的原因是" |
| 回应质疑 | "One might argue"、"为了排除" |
| 限定范围 | "局限"、"不适用于"、适用范围声明 |
| 总结提升 | 章节末、全文末 |

一段可以有两个功能（例如"指出缺口 + 提出方案"），但要分清主次，写成"主要……，同时……"。

### 3. `position` — 在论证结构中的位置

回答四件事：

1. 属于哪一节、该节第几段（用 `sections` 里的节名）；
2. 承接上文什么（点名前一段的具体内容，别写"承接上文"了事）；
3. 引出下文什么；
4. 在全文论证链上处于哪个环节（对应 `argument_map` 的 `stage`）。

句式建议：「引言第 2 段。承接首段提出的 X，把 Y 问题具体化为 Z；为第 3 段引出本文方法的动机做铺垫。位于论证链的"研究缺口"环节。」

## 附加栏（可省略）

- `terms`：本段关键术语，`{"en": "...", "zh": "..."}`。只放影响理解的，3–6 个。
- `questions`：读到这里应该追问的问题，1–3 条。要具体（"该结论是否在低资源语言上成立？"），不要空泛（"这个方法的优缺点是什么？"）。
- `caveat`：存疑之处——疑似笔误、公式誊录不确定、图表未能提取、与常识冲突的地方。

## 质量要求

- `summary` 建议 80–200 字；`function` 60–150 字；`position` 50–120 字。三栏合计不超过 500 字，长段可放宽。
- 每栏必须包含该段的具体信息（术语、数字、主张），删掉段落后注释就不能复用。
- 禁止空话："这一段非常重要"、"作者进行了深入分析"、"为后文奠定了基础"单独出现时无效，必须说明**是什么**奠定了基础。
- 禁止把 `zh` 复制过来当 `summary`；禁止三栏互相复制。
- 注释用中文；专有名词保留英文。
- 自己的判断要与作者的主张分开："作者主张 X"而不是"X 成立"。

## 好坏对照

段落：作者指出已有基准只覆盖英文，因此跨语言结论缺乏依据。

- ❌ `function`：「承上启下，很重要。」——没有信息量。
- ❌ `function`：「指出已有基准只覆盖英文。」——这是 `summary`，不是功能。
- ✅ `function`：「用"基准覆盖不足"这一事实性缺陷，把上一段的"跨语言评估重要"转化为"当前证据不可用"，从而为本文构建多语言基准提供必要性。属于典型的"指出缺口"动作，且缺口是数据层面的，而非方法层面，这决定了后文的贡献必然是资源型贡献。」

- ❌ `position`：「在引言中。」
- ✅ `position`：「引言第 3 段，也是引言中唯一给出具体数字的一段。承接第 2 段对"跨语言评估缺失"的笼统判断，用三项基准的语言覆盖统计把它坐实；紧接着第 4 段将据此提出本文的多语言基准。位于论证链"研究缺口"环节的证据补强处。」

## 与 argument_map 的一致性

每段的 `position` 都应能映射到 `argument_map` 里的某个 `stage`。若映射不上，通常是两种情况：地图缺了一个环节，或这段其实是过渡/重复内容——两者都要在交付说明里点出来。
